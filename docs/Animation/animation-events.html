Animation events

GUIDE · animation / scripting · reacting when playback reaches a moment in a clip

An animation event marks a moment on a clip: the frame a sword connects, a foot lands, an arrow leaves the bow. A glTF clip declares its events in the events list of its clip schema, each at a frame; the engine times each at that frame over the clip's frame rate, so frame 19 of a clip sampled at 30 frames per second is at 19 / 30 = 0.633 seconds. As an Animator plays the clip, each event fires in the frame whose playback reaches its time. The Animator keeps the events it fired in a frame; a script reads them with AnimatorApi.PollEvents, an engine system with GetFiredEvents.

Reading events from a script

Poll every frame an event matters. PollEvents fills a buffer the script owns and returns how many events it wrote; it allocates nothing. Compare names by id: AnimatorApi.EventNameId gives the id an event's NameId holds, and is worth computing once. 

public sealed class KnightImpacts : GameSystem
{
    static readonly ulong Hit = AnimatorApi.EventNameId("hit");
    readonly AnimationEventRecord[] m_Events = new AnimationEventRecord[8];

    // The entity whose Animator plays the attack.
    public uint Knight;

    public override void OnUpdate(float deltaTime)
    {
        int count = AnimatorApi.PollEvents(World, Knight, m_Events);
        for (int i = 0; i < count; ++i)
        {
            if (m_Events[i].NameId == Hit)
                SpawnImpact();
        }
    }
}

What a record holds

FieldMeaning
NameIdThe name's id, AnimatorApi.EventNameId(name) of the whole name.
TimeSecondsThe event's time on its clip, in seconds from the clip's start: its frame over the clip's frame rate.
NameLengthThe name's length in UTF-8 bytes.
NameThe name as a string. Reading it allocates a string each time; a name longer than 64 bytes reads as its first 64 bytes, while NameId and NameLength stay the whole name's. When byte 64 falls inside a character of more than one byte, the name read ends in U+FFFD, the replacement character.

The buffer

A call writes at most the buffer's length and returns the count. When more events fired than fit, the rest wait for the next call, so a script that expects many events in one frame calls again until the count is below the buffer's length. Each event is returned once: a second call in the same frame returns only the events the first left, or none.

The events belong to the Animator, not to the caller: two systems that poll one Animator split its events between them, whichever polls first taking them. Where several parts of a game react to one Animator (sound, effects, gameplay), poll it once a frame and hand the events to each of them.

PollEvents reads an Animator's events on the main thread only, as a system's update does: the animation wave writes them on worker threads. A call from another thread throws InvalidOperationException, as does a call for an entity that is gone or has no Animator.

When an event fires

Each frame, playback moves a clip from the time it had at the frame's start to its time at the frame's end. The events it fires, and their order:

PlaybackFires
Forward, within the clipThe events from the frame's start time up to, not including, its end time, earliest first. An event at time 0 fires in the first frame of play.
A clip that does not loop reaching its endThe clip stops at its end, and the events on its last frame fire in the frame that reaches it, once.
A loop wrappingThe events from the frame's start time to the clip's end, then those from the clip's start up to the frame's end time. A frame longer than the whole clip fires the events from its start time to the clip's end, then those from the clip's start up to its start time: each event once, never twice in one frame.
A section (PlaySection)The section is the loop: events outside it never fire.
Two or more events in one frameIn time order; events on one frame in the order the file lists them.
A seek, a section jump, a clamp into a sectionNothing: the events jumped over do not fire. The next frame plays from the new time, so an event exactly at the new time fires in that frame, as one at time 0 does in the first frame of play.
Paused, or a speed of 0Nothing.
A montage at a negative play rateThe events from the frame's start time down to, not including, its end time, latest first.
A clip of no lengthNothing.

Blends

A clip fires only while its share of the Animator's output pose is above 0. In an animation graph, each blend gives its inputs their share of its own: a two-way blend at weight w gives the first input 1 − w and the second w; a blend space gives each sample it blends that sample's weight; a state machine's transition gives the state it leaves 1 − t and the one it enters t, so the state it leaves fires until the transition ends. A layered blend without a bone mask gives its base 1 − w and its overlay w; under a bone mask, and under an additive layer, the base keeps its share, because it still shows on the bones the layer leaves. A clip blended out entirely fires nothing; one at weight 0.01 fires as at 1.

Without a graph, a crossfade (CrossFadeSeconds) plays two clips: the outgoing clip fires until the fade ends, and the incoming clip from the fade's first frame. The outgoing clip's events come before the incoming clip's in a frame; a graph's come in the order it evaluates its clips.

A montage fires its own events from its first frame to the frame it finishes, whatever its blend weight, while the montage slot's own share is above 0.

An Animator over several skinned meshes plays the same clip on each; its events fire once.

How long events last

The animation wave empties every Animator's events before its playback runs, and fills them as playback crosses events. They stay until the next animation wave begins, so a system that runs after the wave reads that frame's events, and an event nobody reads in its frame is gone the next.

From engine code

An engine system reads an Animator's events with GetFiredEvents(animator) (Engine/Rendering/AnimationEventDispatch.h): a span of FiredEvent, each holding a copy of the AnimationEvent with its Name, Time and payload, in the order they fired. Reading leaves them for scripts. A system that reads them declares a dependency on HumanoidRetarget, the last system in the wave that fires events, so it runs after all of them.

A host that is not C# calls the export behind PollEvents directly: 

GE_Result GE_Animator_PollEventsOnEntity(GE_Handle worldHandle, uint64_t entityId,
                                         GE_AnimationEventRecord* records, int32_t recordCapacity,
                                         int32_t* outCount);

GE_AnimationEventRecord (Scripting/AnimatorABI.h) is the record above: 80 bytes, the name's id, its time, its length and its first 64 bytes. The export returns GE_Result_InvalidArg for a null outCount, a negative capacity or a null buffer with a capacity, GE_Result_NotFound for an entity that is gone or has no Animator, and GE_Result_Fail off the main thread.
