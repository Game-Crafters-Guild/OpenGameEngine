Unity import

GUIDE · assets / editor · bringing scenes from a Unity package into a project

Tools > Import Unity Package... converts the scenes of a Unity package into engine scenes in the open project: static mesh placements, materials, directional and point lights and the scene environment (fog, ambient light, skybox), with the models and textures they reference. It runs inside the editor, from the built-in unity-import package; nothing has to be installed.

Importing a package

  1. Open the project the scenes should land in, then choose Tools > Import Unity Package....
  2. Pick the source: a .unitypackage file with Browse..., or the path of an extracted package folder (the <guid>/pathname and <guid>/asset layout a .unitypackage unpacks to) typed into the field, followed by Enter.
  3. The dialog lists every scene in the package, all selected, and counts the shared models, textures and materials. Clear the scenes you do not want; shared assets are imported once for any selection.
  4. Choose the destination inside the project's assets folder (the assets folder itself by default) and press Import.
  5. If files with the same names already exist at the destination, the dialog lists them and asks before it overwrites anything.
  6. When the import completes, the dialog reports the scenes, entities and materials written, the models and textures brought in, and any reference that did not resolve. Open <scene> opens a converted scene.

What the import writes

OutputWhere
One scene per selected Unity scene<Scene>_unity.scene in the destination
Materials converted from the package's .mat filesMaterials_Unity/
Models the project does not already have (matched by file name, ignoring case)Models_Unity/, under the package's own folder layout
Textures, as source images the engine compiles on importTextures_Unity/
Scope. The importer converts static meshes, materials, directional and point lights and the scene environment. Skinned meshes and characters, cameras, spot and area lights, particles, colliders, scripts and terrain are skipped; the converter README lists every limitation.

Where the converter comes from

The conversion itself is done by the Unity scene converter, an open-source project with its own repository: Game-Crafters-Guild/OpenEngine-Unity-Scene-Converter. Its README documents every conversion rule and a command-line tool that runs the same conversion outside the editor. The unity-import package carries one built copy of it, Tools/UnityConverter.dll, which the editor runs on its own .NET runtime. The assembly targets net9.0 and loads on the editor's .NET 10 runtime until the converter repository re-pins its SDK to .NET 10. Beside it, Tools/UnityConverter.dll.source records where that copy was built from:

LineMeaning
home, commitThe converter repository and the commit the assembly was built from
sdkThe exact .NET SDK version, which the converter repository pins in its global.json
build, outputThe build command and the file it writes
sha256The hash of the vendored file; a rebuild of that commit with that SDK reproduces it exactly

Updating the converter

  1. Land the change in the converter repository.
  2. In a clean checkout of the resulting commit, with the SDK its global.json names installed, run npm run build:dll.
  3. Copy dist/UnityConverter.dll over Tools/UnityConverter.dll in the unity-import package, update the commit, SDK and SHA-256 in Tools/UnityConverter.dll.source, and land both in one change.

The next editor build stages the new assembly with the package; no engine code changes.
