Native User Systems: Lifecycle and the Post-Simulation Hook

A native user system is a C++ struct deriving ECS::SystemBase in a project or package module. The build-time scanner generates its registration; UserSystemAdapter<T> forwards the hooks the struct declares to the engine-owned UserSystemRegistry. This page states where each hook runs in the frame, what it may touch, and how the late presentation hook OnPostSimulation is delivered.

Authoring

#include <GameSDK/System.h>

struct VisibilitySystem : ECS::SystemBase
{
    void OnStart(ECS::World& world);                     // play enters
    void OnUpdate(ECS::World& world, float dt);          // game logic, before the engine simulates
    void OnPostSimulation(ECS::World& world, float dt);  // presentation, after movement, before extraction
    void OnDestroy(ECS::World& world);                   // play exits
};

Every hook is optional; the adapter detects each one with a requires expression and forwards only what the struct declares. EntitySystem<Self> supplies OnUpdate from a ForEach; the other hooks may be added to it as usual.

Why a second hook exists

Game logic belongs before the simulation: OnUpdate sets destinations, desired velocities and inputs that navigation and physics consume in the same frame. A presentation publisher (a visibility mask, a renderer-membership decision) that reads positions in OnUpdate therefore sees last frame's movement while the renderer shows this frame's. OnPostSimulation is the point after the writers have finished and before extraction reads the world.

What the late hook may do

RuleDetail
Derive, do not simulateRead the completed simulation and write presentation inputs: renderer membership (MeshRenderer::renderLayerMask), CPU texture publications, parameter blocks. Do not advance gameplay state, replace the scene or rewrite camera, terrain or hierarchy inputs already consumed earlier in the schedule.
Direct writes reach extractionComponent writes through GetComponentForWrite / GetForWrite land before extraction runs. Deferred commands (Entity::Set, AddComponent) stay deferred and are played back at the next frame's flush; the hook is not a command flush.
Mesh binding is next frameA MeshRenderer whose asset changes in the hook is bound on the main thread before the next frame's waves, so its new geometry appears one frame later. Membership changes appear in the same frame.
CPU texturesA lease created or published inside the hook drains in the same frame: the bridge observes the world scope and runs the CPU texture drain after the hook, before graph declaration. Sources unchanged since the early drain do not upload again.
Exclusive executionThe bridge system declares RequiresExclusiveUpdate: it runs on the thread calling SystemManager::Update with every other system of its wave joined before and after it. Arbitrary user world access needs no further locking.
FaultsThe same guarded invocation as OnUpdate: a thrown exception is logged and the remaining systems still run; a hard fault disables the faulting system for the session.

Delivery

EventBehavior
One tick, one deliveryTickUserSystems records the world id, its lifecycle reset generation and the native delta. The next NativePostSimulationSystem update for that exact world and reset generation delivers the hook once, with that delta, and clears the record before any user code runs. A redraw without a native tick, another view of the world, an unrelated world, or a reentrant call delivers nothing.
StopStopUserSystems revokes the pending delivery before OnDestroy.
Module replacementClearing a module's registrations revokes the pending delivery; the replacement module receives the next tick's delivery. Registrations of other modules are untouched.
World resetA reset before the tick completes, or inside OnUpdate, changes the lifecycle reset generation and revokes the delivery. A fresh tick publishes the current state.
Pause and edit modeNo native tick means no delivery. Existing publications stay valid.

Schedule effect

Mesh extraction declares the movement writers as optional dependencies and the bridge as a required one, so extraction runs after navigation movement, physics write-back, character-controller write-back and ocean buoyancy whenever those systems exist. Objects those writers move are extracted from this frame's positions. The wave solver orders by declared edges only; SystemPhase and Order sort within a wave.

ABI

IUserSystem carries OnPostSimulation and HasPostSimulation, and ECS::ISystem carries RequiresExclusiveUpdate, so the native module ABI version is 2. A module built against an earlier version is refused at load with ABI version mismatch: module=1 host=2 — rebuild user scripts against this engine, before any of its registrations replay. Engine, Editor, Player, the SDK and every native module are rebuilt together.

Verification

NativePostSimulationTests covers adapter detection, once-per-tick delivery with the native delta, revocation on Stop, module replacement and reset, guarded faults, deferred-command semantics, exclusive execution in mixed and legacy parallel waves, and the assembled rendering, physics and navigation schedule placing the bridge after the writers and before extraction. CpuTextureSourceTests drives navigation movement followed by a hook that creates and publishes a lease and reads the pixels back in the same frame. NativeModuleRejectionTests loads an ABI-1 probe and checks it is refused before registration.
