Your first project

Usage guide · editor / projects / export

A project is a folder: its content lives under Assets/, and the editor keeps its own data beside it (.Editor/ for project settings, .Cache/ and AssetDatabase.assetdb for derived data). This page takes a project from the editor's first launch to a game you can run. Build the editor first, as BUILD.md describes.

First launch

Started without a project, the editor opens the last project you used. On the first launch there is none, so it shows the project picker. Hold Shift while the editor starts to get the picker instead of the last project.

The picker's home screen has a New project card, an Open project card and the list of recent projects. Behind the picker the editor holds an empty placeholder project, the default project; it cannot become one of your projects, so the picker stays open until you create or open one.

PlatformDefault project folder
macOS~/Library/Application Support/GameEngine/Editor/DefaultProject
Windows%APPDATA%\GameEngine\Editor\DefaultProject
Linux$XDG_DATA_HOME/GameEngine/Editor/DefaultProject, or ~/.local/share/... when XDG_DATA_HOME is unset

Create a project

1. In the picker, choose New project. The Templates tab lists the built-in templates.
2. Pick a template. Basic 3D starts with a lit scene, Assets/Scenes/Main.scene. Blank starts with an empty Assets/ folder. Open World currently creates an empty project, like Blank.
3. Type a name under PROJECT NAME and choose a folder under LOCATION with Browse. The location must be an existing folder; the editor creates <location>/<name> and refuses a name that already exists there. Keep projects outside the engine checkout and its build/ folder.
4. Choose Create project. The editor opens the new project.

Open a project

  • From the picker: choose a project in the recent list, or choose Open project and then Browse to pick a folder. The editor opens the folder where it is; it does not copy it. The same view can also import a project from a .zip archive or a Git URL.
  • From a running editor: the Open Project Folder button in the top toolbar, or the Open Project command in the search (Cmd+K on macOS, Ctrl+K on Windows and Linux), shows the picker. The editor switches projects without restarting.
  • From the command line: pass --project <folder>. The editor skips the picker and opens that folder, creating it if it does not exist.
# macOS
build/macos-arm64-local/bin/Debug/Apps/Editor/Editor.app/Contents/MacOS/Editor --project ~/GameProjects/MyGame

# Windows
build\vs2026-x64-local\bin\DebugFast\Apps\Editor\Editor.exe --project C:\GameProjects\MyGame

# Linux
./build/linux-x64-local/bin/Debug/Apps/Editor/Editor --project ~/GameProjects/MyGame

Any folder can be opened as a project: the editor creates Assets/ if it is missing.

The C# project for your IDE

Each time it opens a project, the editor writes GameEngine.Scripts.csproj at the project root, beside Assets/. Open that file in your IDE to edit the project's C# scripts: it compiles every .cs file under Assets/ against the engine. A new file the IDE creates at the project's top level lands at the project root, outside Assets/, where nothing compiles it, so create script files inside Assets/. The file is regenerated on every open and holds paths specific to your machine: do not edit it and do not commit it. A copy left inside Assets/ by an older editor is deleted when the project opens, and the Log panel says so.

Save a scene

Press Cmd+S on macOS or Ctrl+S on Windows and Linux, or use the Save Scene button in the top toolbar. A scene that has never been saved asks for a Scene name and a Folder, starting at the project's Assets/ folder; scenes are .scene files. Cmd+Shift+S or Ctrl+Shift+S saves under a new name.

Export your game

The editor exports a game for the platform it runs on: the macOS editor builds macOS games, the Windows editor Windows games. A native export from the Linux editor does not work yet: it looks only for Player.exe. For Linux, build a Steam Deck runtime with build_deck.py, as Steam Deck iteration describes. Publishing to Steam is in Game builds and Steam publishing.

1. Open the Build panel with the Build button in the top toolbar (the game-controller icon), or Window > Build.
2. Choose Settings in the panel. Under Global scene list, drop the scenes to ship from the asset browser onto the list; the first one is the startup scene. A build with no scenes stops with No scenes configured. Game name sets the name of the exported game; without it the game takes the project folder's name.
3. In the platform table, turn On your platform only: Mac or Windows. Windows is on by default. The panel builds one platform at a time, the first one turned on in the table's order.
4. Choose Build. The Progress and Done columns follow the build; the button becomes Cancel while it runs.

The game goes to Build Folder/<Platform> inside the project, for example Build Folder/Mac. Build path in the panel, or Build folder in the platform's settings, chooses another folder; an absolute path still gets the platform folder appended.

PlatformOutputRun it
macOS<Game name>.app, with the game's content inside the bundleOpen the .app from Finder, or open "Build Folder/Mac/<Game name>.app"
Windows<Game name>.exe, game.config and the game's contentRun the .exe

A build replaces the previous output folder only when it has succeeded; until then the previous output is kept. When the folder cannot be replaced, for example because the previous game is still running, the build stops with an error that names the folder. Game builds and Steam publishing explains how the output is replaced, and how to prepare, verify and upload a release.
